# 序列贡献诊断、逐样本保护与0814共享气压验证

## 本轮开发

延续HSMM + Agent结构假设 + C++受约束校准，不增加新的预测模型。新增的是验证假设的工具，而不是替Agent预先写好场景结论。

- `diagnose_context_template`：Agent可选关闭positive、negative或both序列项，重放同一历史，对比活动模板与消融结果。只读、不选参、不提交模板。保留原子观测及已有个性化参数的处理，仅消融序列层。
- 紧凑诊断：每条episode返回前缀首次就绪、完整序列首次匹配、概率首次越线时间、负向命中tick数，以及概率越线后被产品/步行等待门控阻止的tick数。0表示没有观察到。统计覆盖整个窗口，不等于推送前阻塞时长。
- 逐episode保护：对无模板基线和已有模板均检查；不允许新误推替换旧误推、不允许丢掉原本保留的正例，也不允许某条已推送正例变晚。仍保留总分增益和总体分类保护。这个保守规则可能拒绝有合理整体收益的权衡，当前demo优先保护已有提前量。
- 记录隔离：历史行支持`episode_id`，避免不同设备相同时刻的记录合并。未标注episode计入`unscored`，不当成正例或负例。

## Agent如何使用

Agent先提出可证伪假设，再自主选择要检验的序列部分。例如调用：

```json
{"ablation":"positive","limit":100}
```

对应CLI：

```bash
commute_offline_tools ROOT template_diagnose '{"ablation":"positive","limit":100}'
```

它可以区分“模式确实匹配”与“模式改变了推送”；如果负向项没有改变任何结果，就不能仅凭负向规则存在声称它有效。无活动模板时工具拒绝，Agent应先查原始episode；不能通过该工具试探无限结构。工具不是物理因果证明，也不能替代独立真值。

Jiuwen宿主已注册工具，并在diagnostic-only模式开放；原有直接改参/提交工具在该模式仍不可见。prompt只补充证据分析方法，不提示特定传感器或目标答案。

本轮确实尝试了单次限12轮的Jiuwen只读Agent诊断，读取本地凭据但不复制/输出密钥。SDK返回`llm response error`（11003），没有形成归因或审计，theta及活动模板逐字节保持不变。不能将本轮确定性消融结果说成Agent已自主发现的结论。`scripts/run_template_diagnostic_agent.py`保留了隔离复制、超时、状态与不变性检查，后续可在服务恢复后重试；失败日志仅保存在本地。

## 同组共享气压

按用户确认，同一次过程、时间极近的三条采集记录可以共用气压。新增验证脚本支持`--share-group-baro`：

1. 按目录时间分组，组内首尾跨度不超过60秒，不按相邻时间无限串联。
2. 只对恰好三条的组自动共享；优先本条气压，少于50行时选同组具有至少50行气压的最近记录。该行数仅为完整性启发式，不是校准质量保证。
3. 不共享Wi-Fi、GPS、PDR等；不跨组借用。记录`group_id`、`baro_source`、`baro_shared`及本条/源文件行数。
4. 使用原始`wallTsMs`，不以目录时间差平移传感器时钟，不取未来样本。是否真正同步、同路径仍依赖采集约定，不能只靠时间相近自动证明。
5. `run_real_flow.py --local-time-axis`固定本条采集的tick网格和结束边界，防止借入文件改变回放时间轴。共享不会扩展到本条采集之外。

真实手机仍只有本机传感器；组内借用是这套多机同步数据的离线实验设置，不代表解决了真实缺失气压问题。共享后24条记录对应8组过程，不能当24个独立行为样本，后续训练/验证划分也应整组分开。

## 0814冻结验证结果

沿用0812选出的前缀长度1、strength=0.6模板，未在0814上重新选参。共24条设备记录，8组；8条有本条气压，另16条组内借用。

使用GPS来源和锚点向外关系转换生成13条离开代理标签；其余11条保持UNLABELED，不因没有GPS确认就设为负例，也不因出现低层平台就自动转正。因此与旧0812/0813软正评价口径不同。

|气压设置/算法|13条代理正例中的推送数|未推送数|已推送正例平均提前量|11条未标注中的推送数|
|---|---:|---:|---:|---:|
|本条气压，无模板|8|5|40.0秒|10|
|本条气压，冻结模板|9|4|50.0秒|10|
|组内共享，无模板|9|4|41.1秒|8|
|组内共享，冻结模板|11|2|55.5秒|8|

注意：平均提前量只覆盖成功推送的正例，各行分母不同，不能把均值之差直接当成同一批样本的平均收益。未标注的8次推送尚不能计作正确或误报。13条正例也是相关设备记录和GPS代理标签，不是13次独立人工确认事件。

组内共享条件下，关闭正向序列后回到9/13、41.1秒；关闭负向序列后仍为11/13、55.5秒。说明这批窗口中的可观察收益来自正向序列，未显示负向序列改变推送的贡献，不能因此断言负向序列在所有场景无用。

仍未推送的代理正例为163555和163556两条记录。没有针对它们继续调阈值或添加场景补丁。0812/0813回归结果与上一版本相同：平均提前量100.0/71.7秒，现有硬误推和漏报保持0。

## 复现

在WSL、仓库目录执行，输出目录必须不存在：

```bash
python3 scripts/validate_raw_frozen_templates.py \
  --data /mnt/d/0814 \
  --profile output/prefix_lead_verified/train/active_context_template.json \
  --theta output/prefix_lead_verified/train/theta.json \
  --binary sa_cpp/build_github_sync/commute_offline_tools \
  --share-group-baro --output output/0814_shared_reproduction
```

去掉`--share-group-baro`可做独立气压对照。Python用于原始传感器特征提取，C++执行冻结模板/HSMM回放；这不是手机全天在线链路验证。每条采集分别初始化，未部署手机或更新独立SA9902宿主。

测试包括11项C++ smoke、合成连续评分/因果前缀/只读消融/同时间设备隔离/未标注排除测试、共享气压分组测试，以及Jiuwen宿主构建。
